# Запуск «Древа» для семьи: памятка

Что делать по шагам: поставить новую версию на сервер, проверить на телефонах, пригласить родных. И что делать, если что-то пошло не так.

На сервере сейчас стоит первая версия. Обновление её не потеряет: люди, связи, фото, история правок, приглашения и входы родственников сохраняются, перед обновлением установщик сам делает копию базы. «Мы рядом» установщик не трогает.

## 1. Получить код на сервер

Репозиторий закрытый, поэтому нужен вход в GitHub. Подойдёт любой из двух способов.

### Способ А: архив через компьютер

1. На компьютере откройте https://github.com/sicihakif36-spec/drevo (войдите в GitHub).
2. Проверьте, что вверху слева выбрана ветка `main`. Нажмите зелёную кнопку «Code» → «Download ZIP». Скачается `drevo-main.zip`.
3. Перешлите архив на сервер, как делали в прошлый раз, например:
   ```sh
   scp drevo-main.zip ВАШ_ПОЛЬЗОВАТЕЛЬ@АДРЕС_СЕРВЕРА:/tmp/
   ```
   (в Windows удобно через WinSCP).
4. На сервере распакуйте в новую папку:
   ```sh
   sudo rm -rf /srv/drevo/incoming/drevo-main
   sudo mkdir -p /srv/drevo/incoming
   sudo unzip -q /tmp/drevo-main.zip -d /srv/drevo/incoming/
   ```
   Код будет в `/srv/drevo/incoming/drevo-main`.

### Способ Б: `git clone` прямо на сервере

1. В GitHub создайте ключ доступа: аватар справа вверху → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token. Repository access — «Only select repositories» → `drevo`; Permissions → Contents → «Read-only». Срок — например, 30 дней. Скопируйте ключ (он показывается один раз).
2. На сервере:
   ```sh
   sudo mkdir -p /srv/drevo/incoming && cd /srv/drevo/incoming
   sudo git clone --branch main https://github.com/sicihakif36-spec/drevo.git drevo-main
   ```
   На вопрос `Username` — ваш логин GitHub, на `Password` — ключ из пункта 1 (при вставке он не виден, это нормально).
3. В следующий раз вместо клонирования: `cd /srv/drevo/incoming/drevo-main && sudo git pull`.

## 2. Запустить установщик

Перед запуском посмотрите, сколько места на диске: `df -h /` — нужно хотя бы 3 ГБ свободных (сборка образа).

```sh
sudo bash /srv/drevo/incoming/drevo-main/deploy/install.sh
```

Установщик всё делает сам, обычно 3–10 минут:

1. **Копия базы** перед обновлением: `/srv/drevo/backups/drevo-<время>-before-update.dump`. Если копия не получилась, он останавливается и ничего не меняет.
2. Кладёт код в `/srv/drevo/releases/<время>` (прежний выпуск остаётся рядом — для отката).
3. **Собирает** новую версию: скачивает Node.js и ffmpeg (переводит записи голоса в MP3). Серверу нужен доступ к Docker Hub и к зеркалам Debian.
4. **Запускает**; новая версия сама обновляет базу (это несколько секунд) и начинает отвечать.
5. Включает ежедневные копии в 5:40 по Москве: база — 30 дней, все файлы (фото, миниатюры, документы, записи голоса, фото из анкет) — в `/srv/drevo/backups/files`.
6. **Nginx**: ставит новый файл `drevo.conf` и проверяет `nginx -t`. Если проверка не прошла, возвращает прежний файл — сайты на сервере, включая «Мы рядом», работают как раньше.
7. Сертификат уже есть — повторно не получает.

В конце должно быть `== Готово: https://drevo.myryadom.su`. Если установщик остановился с ошибкой — см. раздел 5.

## 3. Проверить сразу после установки

Лучше вдвоём: у вас Android или iPhone и у кого-то из родных — телефон другой системы.

**Всё на месте**

1. Откройте https://drevo.myryadom.su на телефоне, на котором уже входили. Должно открыться дерево **без нового входа**.
2. Проверьте, что все люди на месте: «Люди» — тот же список. Откройте пару карточек: даты, места, заметки как были.
3. Фото: в карточке внизу раздел «Фото и документы» — главное фото и прежние фото этого человека (если фото меняли, старое тоже в альбоме). Фото, которые раньше убирали кнопкой «убрать фото», в альбоме не видны, но их можно вернуть: «Ещё → Последние правки» — там запись об удалении с кнопкой отмены.
4. «Ещё → Последние правки» — видны прежние правки с именами, кто правил.
5. Нажмите на нижней панели «Лента»: старые правки **не** отмечены как новые.

**Уведомления**

6. Android (Chrome): «Ещё → Уведомления» → «Включить уведомления на этом телефоне» → «Разрешить» → «Прислать проверочное». Уведомление должно прийти через несколько секунд. Закройте приложение и попросите кого-то оставить комментарий в карточке — уведомление должно прийти и при закрытом приложении.
7. iPhone (iOS 16.4 и новее): уведомления работают **только с экрана «Домой»**. В Safari откройте сайт → кнопка «Поделиться» (квадрат со стрелкой) → «На экран „Домой“». Откройте «Древо» с новой иконки — должно открыться дерево без нового входа. Дальше — как на Android: «Ещё → Уведомления» → «Включить…» → «Прислать проверочное».
8. Если родные пользуются другим браузером (например, Яндекс Браузер) — включите уведомления и там. Если не включаются — сообщите разработчику, какой браузер.
9. Правки приходят одной сводкой («Елена добавила 3 человек») примерно через 10 минут после того, как человек закончил править; дни рождения и памятные даты — в 9:00 по Москве. Если формулировки или время не нравятся — скажите разработчику.

**Запись голоса**

10. На Android: откройте карточку ушедшего родственника → «Истории» → «+ Рассказать историю» → «Записать голос» → разрешите микрофон → скажите несколько слов → «■ Стоп». Должен появиться плеер: нажмите ▶ — запись должна звучать **до сохранения**. Напишите заголовок → «Сохранить».
11. На iPhone откройте эту же историю и прослушайте. Перемотайте ползунком — должно перематываться.
12. Повторите наоборот: запишите на iPhone, прослушайте на Android. Если есть iPhone со старой системой (iOS 17.3 и раньше) — прослушайте и на нём.
13. Голосовое из WhatsApp или Telegram: сохраните его в телефон, в новой истории нажмите «Выбрать готовую запись» и выберите файл. Прослушайте на iPhone.

**Документы**

14. В карточке «Фото и документы» → «+ Добавить» → «Документы» → выберите PDF побольше (до 20 МБ). Должна пройти загрузка с полосой хода. Нажмите на документ → «Открыть документ» — PDF должен открыться в браузере.
15. Файл больше 20 МБ телефон не отправит и скажет, что файл слишком большой, — так и должно быть.

**Обновления у всех сразу**

16. Откройте приложение на двух телефонах. На одном добавьте человека — на втором он появится через секунду-две без обновления страницы.

Если какой-то пункт не сработал — запишите номер пункта, телефон и что видно на экране (лучше снимок экрана) и передайте разработчику.

## 4. Пригласить родных и разослать анкеты

**Приглашения**: «Ещё → Родственники и приглашения» → «Пригласить». Напишите для себя, кто это («Тётя Валя»), выберите права и нажмите «Создать ссылку», затем «Поделиться» — отправьте в мессенджер. Ссылка открывается один раз и действует 14 дней.

Какие права кому:

- **Участник** — видит всё, добавляет и правит. Тем, кто будет вместе с вами вести дерево.
- **Родственник** — видит всё (даты, места, фото живых), но дерево не правит; может писать в обсуждении у карточки. Пожилым родственникам и детям, чтобы ничего случайно не испортили.
- **Гость** — у живых видит только имена, без дат, мест, заметок и фото. Дальней родне и знакомым.
- **Владелец** — всё, включая приглашения. Лучше никому, кроме себя.

Права можно поменять потом в том же разделе. Если человек сменил телефон — там же у его имени «Вход на новом телефоне».

**Анкеты** — для тех, кто приложением пользоваться не будет: «Ещё → Анкеты для родственников» → «Новая анкета» → для кого (видите только вы) и, если он уже есть в дереве, кто это → «Создать ссылку» → «Поделиться». Человек заполняет без входа, по шагам; ссылка действует 30 дней. Заполненная анкета придёт в ленту и уведомлением; откройте её — для каждого человека выберите «Уже есть», «Новый» или «Пропустить» — и нажмите «Загрузить в дерево». Загрузку можно отменить целиком из «Последних правок».

## 5. Если что-то пошло не так

**Посмотреть журнал приложения** (последние 100 строк):

```sh
sudo docker compose -p drevo --env-file /srv/drevo/.env -f /srv/drevo/current/deploy/docker-compose.yml logs --tail 100 app
```

Журнал базы — то же, но в конце `db` вместо `app`. Состояние контейнеров — `ps` вместо `logs --tail 100 app`.

**Установщик остановился с ошибкой.** Прочитайте последние строки. «Нет A-записи» или «nginx -t не прошёл» — сайт работает как раньше, перешлите сообщение разработчику. «Приложение не запустилось» — перешлите журнал (команда выше) и, если сайт не открывается, откатитесь.

**Откат на прежнюю версию** — если новая версия не запускается или в ней что-то серьёзно не так:

```sh
sudo bash /srv/drevo/current/deploy/rollback.sh
```

Откат покажет, на какой выпуск возвращается и из какой копии базы, и спросит подтверждение — напишите `ДА` (или `yes`). Он:

- сначала сохраняет нынешнюю базу (`/srv/drevo/backups/drevo-<время>-before-rollback.dump`);
- возвращает базу из копии перед обновлением и прежний выпуск кода, запускает его и ставит прежний файл nginx (с проверкой `nginx -t`).

Всё, что родные успели внести после обновления, из дерева пропадёт, но останется в копии `before-rollback` — разработчик сможет перенести. Файлы фото и записей не удаляются. Входы родственников, сделанные до обновления, снова работают. Когда причина найдена, новая версия ставится тем же установщиком (раздел 2).

**Копии.** Лежат в `/srv/drevo/backups`: база — `drevo-<время>.dump` за последние 30 дней, копии перед обновлением и откатом — пока не удалите их сами, файлы — в `files/`. Всё это на том же диске, что и сервер: раз в месяц-два скачивайте папку `backups` к себе (например, через WinSCP) — на случай, если сломается сам сервер.

**Новая ссылка для входа владельца** (потерян телефон):

```sh
sudo bash /srv/drevo/current/deploy/invite.sh "Ваше имя"
```
